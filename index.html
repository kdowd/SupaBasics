Reading data from the penguins table

Before we can secure anything, we need something worth securing. This page connects to a real Supabase database and pulls out all 344 rows — with no login, no password, and no security at all.

Why start here? Right now the penguins table has Row Level Security switched off. That means anyone who knows the project URL and the publishable key can read the whole table — including you, right now, without an account. That is a genuine, extremely common mistake. By the end of the workshop you will know exactly how to close it.

How it works

Four steps, start to finish

Every Supabase page you ever write follows this same shape.

1

Load the Supabase library

A <script> tag pulls the official supabase-js library from a CDN. It is a normal JavaScript file — no build tools, no npm install, no framework. It creates one global object called supabase.

2

Create a client

supabase.createClient(url, key) gives you an object that knows which project to talk to. We store it as db in supabase-config.js so all five pages share one setup.

3

Ask for the data

db.from('penguins').select('*') means “from the penguins table, give me every column.” This is an awaited call, so it hands back a result object rather than freezing the page.

4

Check for an error, then draw

Supabase does not throw when a query fails. It returns { data, error } and expects you to look. Checking error before touching data is the habit that separates working code from mysterious blank screens.

The data is messier than it looks. 11 rows have the text NA in the sex column, and 2 rows use 0 for every measurement. Neither is a real missing value — a person typed a placeholder instead. Notice that the dash-we-print-for-null rule in the code almost never fires here, because this table contains no true null values at all. Deciding what counts as “missing” is a data problem, not an authentication problem — but you will usually meet both at the same time.

Careful with big tables. Supabase returns a maximum of 1000 rows per request by default. Our table has 344, so we get all of them by luck rather than by design. If your table had 50,000 rows, this page would silently show only the first 1000 and you would probably never notice. Real apps ask for pages of data, or ask for a count first.

Reference

The entire data-fetching script

This is the whole thing — nothing has been hidden. Read it top to bottom and compare it against the four steps above. 

// 1. The library is already loaded (see the <script> tags at the
//    bottom of this file). 2. The client already exists as `db`
//    (see supabase-config.js).

// 3. Ask the database for everything in the penguins table.
const { data, error } = await db
  .from('penguins')     // which table?
  .select('*')          // which columns? (* = all of them)
  .order('id', { ascending: true });

// 4. Always check the error BEFORE you use the data.
if (error) {
  console.error('The query failed:', error.message);
} else {
  console.log('We got', data.length, 'rows');
  console.table(data);        // try this in your own console!
}
Under the hood

What just happened?

When this page loaded, your browser sent an HTTP request that looked roughly like this: 

GET /rest/v1/penguins?select=*

apikey: sb_publishable_ONnalS_8pdIUH2Qrsz67CA_z4Wco9I2
Authorization: Bearer sb_publishable_ONnalS_8pdIUH2Qrsz67CA_z4Wco9I2

No username. No password. No session token. Just the publishable key, which is sitting in plain text in supabase-config.js where anyone can read it. And the database said yes and handed over all 344 rows.

This is the problem we are about to solve. The publishable key is not the flaw — it is supposed to be public. The flaw is that the penguins table has no Row Level Security, so Supabase has no rule to consult before answering. With RLS switched off, “who is asking?” never gets asked, and everyone is effectively a full member of staff.

Delete the key from supabase-config.js and this page breaks completely — that is the only lock currently on the door, and it is printed on the outside of the door.
